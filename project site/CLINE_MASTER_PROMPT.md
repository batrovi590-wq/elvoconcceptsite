# ELVO / ЖК «Белогорье» — мастер-промпт для Cline

Ты работаешь в VS Code в расширении Cline. Для запросов выбрана GLM 5.3 Flash через OpenRouter. Твоя задача — не придумать новый дизайн, а максимально точно перенести приложенный PDF-макет в работающий адаптивный одностраничный сайт.

## 0. Сначала изучи материалы и репозиторий

В корне проекта/пакета доступны:
- `references/landing-design.pdf` — эталонный длинный макет страницы.
- `references/landing-design-preview.jpg` — визуальный preview макета для быстрого осмотра.
- `references/application-form-design.pdf` — эталон дизайна формы заявки.
- `references/application-form-preview.jpg` — preview формы.
- `public/images/hero-complex.jpg` — главное фото первого экрана, извлечено из макета.
- `public/images/philosophy-terrace.jpg` — фото террасы для блока «Философия проекта».
- `public/images/architecture-card.jpg` — изображение архитектурной карточки из макета.
- `public/images/interior-main.jpg` — исходное главное изображение интерьера/галереи.
- `public/images/gallery-building-view.png` — дополнительное фото комплекса для слайдера.
- `public/images/gallery-terrace-view.png` — дополнительное фото террасы для слайдера.

Прежде чем менять код, посмотри структуру текущего workspace, `package.json`, имеющиеся компоненты, стили и зависимости. Не удаляй и не переписывай существующую работающую реализацию вслепую. Если проект пустой, создай лёгкий проект React + Vite + TypeScript. Если стек уже существует и подходит для задачи — используй его.

Не останавливайся только на плане: после короткой проверки структуры реализуй сайт, запусти доступные проверки и исправь ошибки. Если обнаружишь риск потери пользовательских файлов или необходимость разрушительного действия, остановись и спроси подтверждение.

## 1. Главная цель и ограничения

- Создать **один лендинг**, не многостраничный сайт.
- Воспроизвести PDF-макет как можно ближе: порядок секций, пропорции, отступы, размеры и скругления изображений, расположение текста, цвета, типографику и асимметричную композицию.
- PDF — главный визуальный источник истины. Не заменяй его своим шаблоном и не добавляй секции, которых нет в дизайне, без необходимости.
- Используй предоставленные изображения. Не генерируй новые, не подменяй их случайными стоковыми фото и не используй PDF-страницу целиком как один фон вместо HTML-текста и отдельных изображений.
- Сохрани текст, указанный ниже. Можно корректировать переносы строк под адаптивность, но не менять смысл и не придумывать подтверждённые факты о реальном ЖК.
- Это концепт-сайт. Не выдумывай адрес, стоимость, сроки сдачи, инфраструктуру, наличие квартир, реальные контакты или прочие сведения, которых нет в материалах.
- Не подключай фальшивую базу данных, CRM, API, оплату или внешний сервис для формы. Для текущего демонстрационного сайта это не требуется.
- Не помещай API-ключ OpenRouter в сайт, `.env` фронтенда или клиентский JavaScript. OpenRouter используется только для работы Cline; сам сайт не должен обращаться к OpenRouter.

## 2. Визуальное направление

Сохрани стиль эталона:
- фон всей страницы — тёплый молочно-белый;
- основные тёмные элементы — глубокий приглушённый зелёный;
- дополнительные фоны — светлый песочный/камень;
- текст — графитовый и мягкий серо-оливковый;
- изображения — большие, с мягкими скруглениями;
- крупные заголовки с изящным serif-рисунком;
- мелкие подписи и основной текст — чистый sans-serif;
- тонкие горизонтальные разделители;
- щедрые промежутки между секциями, но никаких необъяснимых пустых провалов;
- минимализм и плавные микроанимации без перегруженных эффектов.

Начальные CSS-переменные (если подбор точных цветов из PDF невозможен, начни с них и сравни визуально):
- `--color-bg: #F6F5F0`
- `--color-surface: #E8E4DA`
- `--color-text: #252720`
- `--color-green: #303B32`
- `--color-accent: #A5AD96`
- `--color-muted: #77786F`
- `--color-line: #D9D7CE`

Типографика по визуальному направлению:
- заголовки — `Cormorant Garamond` (Medium/Semibold, где доступен);
- навигация, абзацы, кнопки и подписи — `Manrope`;
- добавь корректные fallback-шрифты;
- избегай дефолтного жирного Arial/Inter, если они заметно ломают характер макета;
- не используй слишком мелкий текст: на широком desktop основной текст обычно 14–17 CSS px, мелкие подписи 10–12 CSS px; для мобильной версии не опускай основной текст ниже комфортного чтения.

Если шрифты загружаются из Google Fonts, сделай это в одном месте и добавь fallback. Сайт должен оставаться читаемым, если внешний шрифт не загрузился.

## 3. Структура страницы — соблюдай порядок PDF

### A. Header
Логотип слева:
- `БЕЛОГОРЬЕ`
- подпись `ЖИЛОЙ КОМПЛЕКС · СОЧИ`

Навигация по одной странице:
- `О проекте`
- `Архитектура`
- `Интерьеры`

Справа — округлая тёмно-зелёная кнопка с небольшим inline SVG телефона и текстом `Связаться с нами`.

Это anchor navigation, а не переход на отдельные страницы. Сделай плавную прокрутку к соответствующим секциям. Учти `scroll-margin-top`, чтобы заголовки не прятались под фиксированной шапкой, если решишь сделать её sticky.

### B. Hero — большая фотография здания у моря
Используй `public/images/hero-complex.jpg` как главное фото, с `object-fit: cover`, корректным `object-position` и мягким радиусом как в PDF. На desktop фото и блок должны передавать композицию референса: здание преимущественно справа, свободное светлое небо/море слева для текста.

Текст:
- маленькая надпись `Современная жилая архитектура`
- заголовок в переносах, близких к PDF: `Пространство,` / `в котором хочется` / `остаться...`
- описание: `Природное окружение и новый взгляд на жизнь у Чёрного моря.`
- кнопка `Познакомиться с проектом` со стрелкой вправо.

Кнопка скроллит к секции «Философия проекта»/обо всём проекте. Не должна быть декоративной.

Важное: не добавляй под текстом тяжёлую непрозрачную плашку. Сначала попробуй читаемый текст на свободной левой части фотографии. На мобильном перестрой hero: текст обязан оставаться контрастным, здание и смысловой фрагмент фото не должны обрезаться случайным образом.

### C. Три преимущества
Секция с тремя равноправными колонками и тонкими разделителями/нижними линиями как в PDF.

Карточка 1:
- `Архитектура в гармонии с природой`
- `Натуральные материалы, выразительные формы и внимание к деталям.`

Карточка 2:
- `Пространство и свет`
- `Продуманные планировки и панорамные виды.`

Карточка 3:
- `Комфорт в деталях`
- `Эстетика, которая чувствуется в мелочах.`

Карточки в первую очередь информационные; не делай вид, что они ведут на несуществующие страницы. Если hover применён, он должен быть ненавязчивым и не намекать на кликабельность там, где её нет.

### D. «Философия проекта»
Сохрани заголовок `Философия проекта`.

Композиция desktop: слева широкое фото террасы `public/images/philosophy-terrace.jpg`; справа две тёмно-зелёные карточки.

Карточка 1:
- заголовок `Меньше шума. Больше жизни.`
- короткие строки `Свой ритм.` / `Своё пространство.` / `Свои правила.`

Карточка 2:
- заголовок `Ближе к природе. Ближе к себе.`
- текст `Архитектура, которая оставляет главное — ощущение дома.`

На mobile перестрой карточки в вертикальный стек, не уменьшая шрифты до нечитаемого размера.

### E. Секция эстетики и интерьеров
Слева текст, справа высокая/вертикальная карточка с `public/images/architecture-card.jpg`, пропорциями и скруглениями, близкими к PDF.

Левый текст:
- заголовок `Продуманная эстетика для каждого вашего дня.`
- абзац `Натуральные материалы, мягкие оттенки и выразительные фактуры создают гармоничный интерьер с атмосферой уюта, лёгкости и спокойствия.`
- кнопка `Смотреть интерьеры`

Текст на верхней части правой карточки:
`Панорамные окна наполняют комнаты светом и открывают виды на природу Сочи.`

Кнопка `Смотреть интерьеры` должна плавно прокручивать к галерее-слайдеру ниже.

### F. Галерея / слайдер фотографий
В PDF ниже расположен широкий интерьерный слайд слева и текст справа. Сохрани эту асимметричную структуру.

Собери настоящий слайдер на 3 изображения:
1. `public/images/interior-main.jpg` — главный интерьерный кадр из макета;
2. `public/images/gallery-building-view.png` — дополнительный кадр комплекса;
3. `public/images/gallery-terrace-view.png` — дополнительный кадр террасы.

Именно два дополнительных изображения должны переключаться в том же месте, где расположен блок с интерьерной фотографией. Не вставляй их отдельными большими секциями ниже.

Текст справа:
- заголовок `Место, где всё становится чуть спокойнее`
- абзац `Белогорье — концепция жилого пространства, в котором архитектура не спорит с природой. Свет, фактура материалов и открытые виды создают ощущение гармонии и помогают переключиться на собственный ритм.`

Слайдер обязан работать:
- кнопки «предыдущее» и «следующее»;
- точки-индикаторы, каждая переключает на соответствующий слайд;
- при переходе обновляются и фото, и `alt`/подпись;
- плавный fade/slide без мерцания и layout shift;
- кнопки имеют доступные `aria-label`;
- клавиатурный фокус виден;
- не включай автопрокрутку без запроса пользователя;
- если изображение временно не загрузилось, покажи аккуратный fallback, не ломая весь layout.

Если добавишь подписи, делай кратко и честно: `Интерьер гостиной`, `Архитектура комплекса`, `Терраса с видом на побережье`. Не представляй дополнительные изображения экстерьера как интерьер.

## 4. Форма связи — отдельная модалка поверх лендинга

Используй `references/application-form-design.pdf` и `references/application-form-preview.jpg` как главный визуальный источник формы.

Модалка открывается при клике на `Связаться с нами`. На desktop — аккуратная карточка по центру на полупрозрачном затемнённом фоне, кремовая поверхность, светлая внешняя рамка/контур, большие округления, мягкая тень. На mobile карточка не должна выходить за границы экрана; внутренние поля и кнопка остаются удобными для касания.

Содержание формы:
- заголовок `Мы с вами свяжемся!`
- поле с placeholder `Ваше имя`
- поле с placeholder `Номер телефона`
- информационная подпись точно по смыслу: `Это концептуальная версия сайта ЖК «Белогорье». Форма работает в демонстрационном режиме: данные не отправляются и заявки не принимаются.`
- кнопка `Оставить заявку`

В PDF круг рядом с примечанием выглядит как индикатор. Не делай его обязательным consent-checkbox без причины; лучше реализуй как маленькую informational icon/circle рядом с пояснением.

Форма должна вести себя честно:
- имя и телефон валидируются в браузере;
- телефон визуально форматируется/принимает российский формат, но не блокируй ввод международного номера слишком жёстко;
- ошибки показываются рядом с соответствующим полем и доступны для screen readers;
- submit не делает сетевой запрос, не сохраняет значения в localStorage/sessionStorage, не отправляет сообщения и не создаёт фальшивую заявку;
- после корректного submit показать явное сообщение: `Это демонстрационная форма — данные не отправлены.` Не обещай реальный звонок, несмотря на текст заголовка;
- после сообщения очисти форму либо предложи закрыть её;
- modal закрывается кнопкой-крестиком, кликом по фону и клавишей Escape;
- при открытой модалке фокус переходит в неё и не уходит за её пределы; после закрытия фокус возвращается на кнопку, которая её открыла; останови прокрутку фона;
- не добавляй fake backend или выдуманные API endpoints.

Все кнопки и ссылки должны иметь понятное действие. Никаких `href="#"`, пустых onClick и декоративных кнопок без функции.

## 5. Анимации и микроинтеракции

Добавь аккуратные, плавные и дорогие по ощущению анимации, не меняя общий дизайн:
- кнопки: лёгкое изменение цвета и подъём на 1–2 px при hover, быстрый мягкий переход;
- стрелки в кнопках могут сдвигаться на 2–4 px;
- интерактивные ссылки — понятный hover/focus;
- модалка: короткий fade + небольшое scale-in; фон постепенно появляется;
- слайдер: fade/translate примерно 250–400 ms, без резкого прыжка размера;
- карточки: очень лёгкий визуальный отклик только если они являются интерактивными элементами;
- появление секций при скролле — мягко и с небольшой задержкой; используй IntersectionObserver только если это не приводит к тому, что контент остаётся невидимым;
- поддержи `prefers-reduced-motion: reduce`: отключай/сокращай необязательные эффекты;
- не используй агрессивный parallax, бесконечные фоновые движения, прыгающие элементы или длинные анимации.

## 6. Техническая организация

Если проект пустой, используй:
- React + Vite + TypeScript;
- обычный CSS с переменными и адаптивными media queries (без тяжёлой UI-библиотеки);
- inline SVG для телефона, стрелок и закрытия, чтобы иконки были чёткими и не зависели от эмодзи;
- не используй backend/database, поскольку форма явно демонстрационная.

Предлагаемая структура:

```text
src/
  components/
    Header.tsx
    Hero.tsx
    FeatureGrid.tsx
    PhilosophySection.tsx
    InteriorFeature.tsx
    InteriorCarousel.tsx
    ContactModal.tsx
    Footer.tsx
  data/
    siteContent.ts
  hooks/
    useScrollReveal.ts      # только если действительно нужен
  styles/
    tokens.css
    global.css
  App.tsx
  main.tsx
public/
  images/
    hero-complex.jpg
    philosophy-terrace.jpg
    architecture-card.jpg
    interior-main.jpg
    gallery-building-view.png
    gallery-terrace-view.png
references/
  landing-design.pdf
  landing-design-preview.jpg
  application-form-design.pdf
  application-form-preview.jpg
README.md
```

Если в существующем проекте уже есть другая разумная структура, не перестраивай её ради совпадения с этим деревом; важнее ясное разделение компонентов, контента, стилей и изображений.

Требования к коду:
- TypeScript без `any` без необходимости;
- избегай огромного монолитного `App.tsx`;
- повторяющийся контент храни в `src/data/siteContent.ts` или аналогичном файле;
- используй понятные имена компонентов и CSS-классов;
- не дублируй одинаковые правила CSS;
- alt-тексты у содержательных изображений;
- правильная семантика `header`, `nav`, `main`, `section`, `footer`, `button`, `form`;
- клавиатурная доступность, видимые focus-стили, достаточная контрастность;
- никаких фиктивных ссылок, API-ключей, лишних библиотек или предупреждений React в консоли.

## 7. Адаптивность

Проверь как минимум эти ширины:
- desktop: 1440 px;
- laptop: 1024 px;
- tablet: 768 px;
- mobile: 390 px.

На desktop придерживайся PDF-композиции: hero с текстом слева и зданием справа; три преимущества в ряд; фото террасы с двумя карточками философии; блок эстетики с текстом слева и вертикальным изображением справа; нижний слайдер с изображением слева и описанием справа.

На tablet можно уменьшать промежутки и размеры заголовков, но не ломать порядок.

На mobile:
- header переходит в компактную мобильную навигацию;
- секции складываются в одну колонку;
- изображения сохраняют подходящее кадрирование;
- все тексты полностью видны;
- кнопки не выходят за экран;
- слайдер и модалка работают пальцем и клавиатурой;
- не допускай горизонтального overflow.

## 8. Проверка и завершение

После реализации:
1. Установи зависимости только если необходимо и без ненужных пакетов.
2. Запусти `npm run build` (или эквивалент текущего проекта) и исправь ошибки TypeScript/build.
3. Если доступен браузер или скриншотный инструмент, открой страницу и сравни full-page screenshot с `references/landing-design-preview.jpg`. Корректируй отступы, размеры и порядок секций по сравнению с референсом, а не по вкусу с нуля.
4. Проверь все действия: меню, hero CTA, кнопку контакта, крестик, backdrop, Escape, валидацию формы, демонстрационную отправку, слайдер arrows/dots и CTA «Смотреть интерьеры».
5. Проверь мобильную ширину 390 px и отсутствие горизонтальной прокрутки.
6. Убедись, что страница не отправляет и не сохраняет данные формы.
7. Подготовь `README.md` с описанием стека, структуры проекта, запуска локально и сборки:
   - `npm install`
   - `npm run dev`
